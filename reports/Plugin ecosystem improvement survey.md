# Test bioinfo-lab before adding anything

The highest-value changes to `bioinfo-lab` v1.5.0 are measurement and enforcement, not new content. The plugin has 24 skills, 10 agents, and no evals, hooks, or tests, so no one knows whether its descriptions trigger or whether its prose rules (patient data stays local, write only in the working directory, lint before saving) are followed. Anthropic now ships `claude plugin eval` with a no-plugin baseline, and independent tests show skills often go unloaded: in one vendor benchmark a skill was never invoked in **56% of cases** ([Vercel](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Hooks can turn the privacy rules into mechanical checks. After that, three content updates have clear sources: the ClinGen calibration of PP3/BP4 predictors, the ACMG SF v3.3 list, and ONT version pinning. Bioinformatics MCP servers exist but are mostly single-maintainer projects, and the privacy constraint makes them a late, opt-in, local-only item. Most evidence below comes from WebFetch page summaries or search snippets, not full reads; section 3 grades each recommendation. Statements marked "inference" are the synthesis of the researchers or of this report, not findings.

## Eight changes ranked by value per effort

Effort is S (hours), M (days), L (weeks). Risk is the chance the change harms current behavior.

| # | Change | Evidence | Effort / risk | Expected benefit |
|---|---|---|---|---|
| 1 | Add `evals/` with 2 should-trigger, 2 near-miss, and 1 collision prompt per key skill (writing, plotting, translator, lab-team, variant-interpretation); add `claude plugin validate --strict` to CI. Use deterministic graders first (`regex`, `file_exists`, `tool_used`), `llm` graders only for short rubrics. | `plugin eval` runs 3 times per case against a no-plugin baseline and reports delta; a common first finding is the Skill tool not firing ([docs](https://code.claude.com/docs/en/plugin-evals.md)). Agent Skills guidance: about 20 queries, 60/40 split ([agentskills.io](https://agentskills.io/skill-creation/optimizing-descriptions)). | S-M / low. Each run bills model calls. | Shows which skills add value (delta) and which fail to trigger. Skills with delta near zero are candidates to cut. |
| 2 | Audit all 24 descriptions: key use case first (listing text is cut at 1,536 characters), one or two sentences, explicit "not for" boundaries between writing/translator/project-readme and plotting/slides. Run `/skill-doctor`. Set `disable-model-invocation: true` on niche skills. | Listing limit and `disable-model-invocation` ([Claude Code skills](https://code.claude.com/docs/en/skills)); best-practice limits ([Anthropic](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). | S / low | Lower every-turn context cost; fewer misfires. Rewording alone may not raise recall: one test of three styles gave identical 46% train scores ([Sogl](https://dev.to/danielsogl/skills-without-evals-are-just-markdown-and-hope-3a71)), so judge by eval 1, not by taste. |
| 3 | Move must-always-apply rules (patient data, write scope, scratch rule) out of a skill the model must choose to open. Add a `UserPromptSubmit` forced-evaluation hook that requires a written yes/no per relevant skill. | In 250 sandboxed invocations a one-line reminder hook gave no gain (59% vs 55%) while a forced-evaluation hook reached 100% with 0 false positives on 5 negatives ([Spence](https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals)). Multi-agent variants lost 39-70% on sequential tasks ([Google Research](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)). | S / low | Supports the existing "PI does the thinking" rule with evidence and reduces wasted delegation. |
| 6 | Reviewer agent: pass the artifact and claim list, not the author's reasoning; require executable checks (recompute numbers from the analysis-log script, run tests). | LLMs do not self-correct reasoning without external feedback ([Huang et al.](https://arxiv.org/abs/2310.01798v1)); judges flip after authority cues ([EACL 2026](https://preview.aclanthology.org/ingest-eacl/2026.findings-eacl.70.pdf)). Anchoring on author text was not tested directly (inference). | S / low | Fewer missed errors in claim audits. |
| 7 | Update `variant-interpretation`: pre-specify one predictor and use ClinGen-calibrated thresholds (strength up to Strong) for PP3/BP4; add AlphaMissense, ESM1b, VARITY; record the framework version; add an "SVC v4.0 transition" note without encoding v4 points until published; set ACMG SF at v3.3 with a "check for newer" line; HGVS 21.x with MANE Select; keep the 2020 CNV points framework. Four smaller items follow in order. (9) Tighten the prose lint list using excess-frequency data: flag rare high-ratio words such as delves (r = 28.0) and underscores (r = 13.8), but flag common words such as crucial and potential only by density ([Kobak et al.](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12219543/)); S effort. (10) Scan the plugin's own files in CI with a skill scanner and avoid any text that fetches remote instructions, following the supply-chain findings ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub), [K-Dense report](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/docs/security-report.md)); S. (11) Add a reporting-checklist reference starting with TRIPOD+AI for polygenic and prediction models ([BMJ 2024](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11025451/)); other checklists are unsourced, so S for one item. (12) Add a short Taiwan regulatory reference (Human Subjects Research Act, Human Biobank Management Act, PDPA amendment promulgated 11 Nov 2025 with an unconfirmed effective date) ([Baker McKenzie](https://www.bakermckenzie.com/en/insight/publications/alerts/2025/10/taiwan-amendment-to-personal-data-protection-act)); S, medium risk of staleness.

## MCP servers belong in an opt-in companion plugin

The notes support one packaging design and no more. Keep `bioinfo-lab` MCP-free. If servers are wanted, publish a second plugin with `defaultEnabled: false`, pinned versions, a PreToolUse argument screen, and a skill that states the identifiers-only rule (inference built on the plugin reference, [docs](https://code.claude.com/docs/en/plugins-reference)). Plugin MCP tools carry long names (`mcp__plugin_<plugin>_<server>__<tool>`), and a hook written against the bare server name never fires ([hooks docs](https://code.claude.com/docs/en/hooks)). Settings files skip parenthesized MCP argument rules ([permissions](https://code.claude.com/docs/en/permissions)), so argument screening needs a hook.

Candidates, in order of fit for a human-genetics lab: BioMCP, which runs locally over stdio, covers 72 sources including ClinVar, gnomAD, and CPIC, and states no telemetry, but is vendor-maintained with an oncology focus ([GitHub](https://github.com/genomoncology/biomcp)); the EBI GWAS Catalog server, official, no token ([EBI](https://www.ebi.ac.uk/gwas/docs/programmatic-access/mcp-server)); Anthropic-hosted PubMed and bioRxiv, which the user's host already has through the bio-research plugin, so recommending beats bundling. The GeneFoundry "-link" servers for ClinVar, VEP, ClinGen, and GenCC fit rare-disease work, but each has 0 to 1 stars and was updated in the past week ([topic page](https://github.com/topics/genefoundry)); self-host only. Remote servers receive whatever the model writes into arguments, and a local stdio server still calls public APIs upstream, so a query containing a sample ID leaves the machine either way. The lethal-trifecta analysis ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)) and tool-poisoning work ([Invariant Labs](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks)) support the rule not to run MCP-enabled sessions that have read patient files. Effort is L and risk high, which is why this ranks below items 1 to 8. Livestock and AnimalQTLdb have no MCP server, so `trusted-sources` web lookups stay.

## What not to adopt

Breadth-first collections are the first exclusion. K-Dense has 177 skills and about 56k stars, but its own scan found 472 findings, 18 skills rated not safe, and self-citation instructions telling the agent to fetch the vendor's paper ([report](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/docs/security-report.md)). GPTomics/bioSkills (561 skills) is archived ([GitHub](https://github.com/GPTomics/bioSkills)). SciAgent-Skills claims 92.0% against a 65.3% baseline with no methodology ([GitHub](https://github.com/jaechang-hits/SciAgent-Skills)). Read them for ideas; do not vendor them, because licenses vary per skill and the user prefers a compact plugin.

Second, third-party hosted MCP endpoints. The genefoundry.org router and the public Ensembl instance at ensembl.caseyjhand.com are run by individuals, and their logging and retention policies were not found ([router](https://github.com/berntpopp/genefoundry-router)). Public Galaxy servers receive uploaded data ([Galaxy MCP](https://github.com/galaxyproject/galaxy-mcp)), and ClinicalTrials.gov `search_by_eligibility` takes patient criteria; deny both outright. BioRender duplicates the lab's own plotting skill.

Third, a Haiku-classifier activation hook: it reached 100% activation but falsely activated on 4 of 5 negatives ([Spence](https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals)). Also skip renaming 24 skills to gerunds (a preference, not a rule), multi-agent delegation by default, and ACMG strength for AlphaGenome, which is calibrated for neither PP3 nor BP4. The OpenAI life-science plugin path is unverified, so it is not a source. Plugin `memory` and `userConfig` are low value for a single-lab plugin (inference).

## Open gaps for a second pass

Long-read benchmarks: search PubMed for GIAB HG002 ONT SV comparisons of Sniffles2, cuteSV, SVIM, and Severus; also modkit, phasing tools, and GRCh38 against T2T-CHM13 calling. Reproducibility and provenance: nothing was collected on W3C PROV, RO-Crate, or claim-ledger practice, and the claim that executable recomputation beats LLM review is an inference. Breeding software: only REGENIE, SAIGE, and fastGWA papers were retrieved ([REGENIE](https://link.springer.com/10.1038/s41588-021-00870-7)); BGLR, sommer, blupf90+, ASReml, and rrBLUP versions, licenses, and Crop Ontology resources are unsourced. CPIC and PharmVar: no primary source found, including Taiwan HLA-B*15:02 and HLA-A*31:01 guidance. Reporting checklists: STREGA, STARD, MI-CLAIM, and CONSORT-AI are unsourced. Last-commit dates: not exposed for nearly every repo; run `gh api repos/<owner>/<repo> --jq .pushed_at` for BioMCP, galaxy-mcp, GeneFoundry, and K-Dense before relying on any of them. Also unread: the SVC v4.0 final text, ClinGen SVI splicing and PVS1 updates, update and release-channel behavior for plugins, whether Anthropic-hosted MCP servers log queries, and the original "How We Use Skills" post.
